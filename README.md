# streamstats — потоковый анализатор файлов событий

Лабораторная работа № 2. Пакет `streamstats` читает события из CSV и JSONL файлов, проверяет их, считает статистику и сохраняет JSON-отчёт. Файлы обрабатываются построчно: в памяти хранятся только текущая запись и итоги, а не все события.

## Требования

- Python 3.12 или выше;
- библиотеки, указанные в `requirements.txt`.

Установка библиотек:

```bash
pip install -r requirements.txt
```

## Использование

```text
python -m streamstats analyze INPUT [INPUT ...] --format csv|jsonl [--output REPORT.json] [--skip-invalid]
```

| Аргумент | Описание |
|---|---|
| `INPUT [INPUT ...]` | один или несколько входных файлов. Все файлы должны быть в одном формате. Статистика объединяется в один отчёт |
| `--format csv\|jsonl` | формат входных файлов (обязательный) |
| `--output REPORT.json` | куда сохранить отчёт. Если не указан, отчёт сохраняется в `report.json` в текущей папке (существующий файл перезаписывается) |
| `--skip-invalid` | пропускать ошибочные строки вместо остановки |

Справка:

```bash
python -m streamstats --help
python -m streamstats analyze --help
```

### Примеры

```bash
# один файл, отчёт в report.json
python -m streamstats analyze ../data/events.csv --format csv

# несколько файлов, свой путь к отчёту
python -m streamstats analyze ../data/a.jsonl data/b.jsonl --format jsonl --output out/report.json

# пропускать ошибочные строки
python -m streamstats analyze ../data/events.jsonl --format jsonl --skip-invalid
```

## Формат входных данных

Каждое событие состоит из четырёх обязательных полей:

| Поле | Требование |
|---|---|
| `timestamp` | время в формате ISO 8601 |
| `level` | одно из `DEBUG`, `INFO`, `WARNING`, `ERROR`, `CRITICAL` (регистр важен) |
| `source` | непустая строка |
| `message` | строка (пустая строка допустима) |

**CSV** — первая строка это заголовок `timestamp,level,source,message`. Значения с запятой берутся в кавычки:

```csv
timestamp,level,source,message
2026-10-07T12:00:00+03:00,INFO,loader,Начало чтения файла
2026-10-07T12:01:10+03:00,WARNING,loader,"Файл большой, чтение займёт время"
```

**JSONL** — по одному JSON-объекту в строке:

```jsonl
{"timestamp":"2026-10-07T09:06:00+00:00","level":"INFO","source":"web","message":"Получен запрос"}
{"timestamp":"2026-10-07T09:07:15+00:00","level":"ERROR","source":"web","message":"Ошибка 500"}
```

Пустые строки в JSONL пропускаются. Файлы читаются в кодировке UTF-8.

### Что считается ошибочной строкой

- отсутствует любое из обязательных полей (в CSV — строка короче заголовка);
- `level` не из списка допустимых значений;
- `source` пустой или состоит из одних пробелов;
- `message` не является строкой;
- `timestamp` не разбирается как ISO 8601;
- в JSONL: синтаксически неверный JSON или значение, не являющееся объектом.

Время без указания часового пояса считается временем в UTC. Время сравнивается как момент (`datetime`), а не как текст: `12:00+03:00` и `09:00+00:00` — один и тот же момент.

## Отчёт

Отчёт — JSON-файл (UTF-8, кириллица сохраняется как есть):

```json
{
  "total_events": 3,
  "levels": {"INFO": 1, "ERROR": 2},
  "sources": {"web": 2, "db": 1},
  "top_error_sources": [
    {"source": "db", "count": 1},
    {"source": "web", "count": 1}
  ],
  "first_timestamp": "2026-10-07T09:10:00+00:00",
  "last_timestamp": "2026-10-07T09:15:00+00:00",
  "skipped_invalid": 0
}
```

| Ключ | Значение |
|---|---|
| `total_events` | число корректных событий всех уровней |
| `levels` | число событий каждого уровня |
| `sources` | число событий каждого источника |
| `top_error_sources` | до 5 источников с наибольшим числом событий уровня ERROR/CRITICAL |
| `first_timestamp`, `last_timestamp` | самая ранняя и самая поздняя метка (`null`, если событий нет) |
| `skipped_invalid` | число пропущенных строк (при `--skip-invalid`) |

**Порядок при равных счётчиках** в `top_error_sources`: сначала больший счётчик, при равенстве — по названию источника в алфавитном порядке. Результат одинаков на одинаковых входных данных.

## Обработка ошибок

| Режим | Поведение при ошибочной строке |
|---|---|
| по умолчанию | обработка останавливается, в stderr выводится файл и номер строки, отчёт не создаётся, код возврата `2` |
| `--skip-invalid` | строка пропускается, в лог пишется `WARNING`, число пропусков попадает в отчёт, обработка продолжается |

Номер строки относится к исходному файлу, а не к числу успешно прочитанных событий.

### Коды возврата

| Код | Значение |
|---|---|
| `0` | успех |
| `2` | ошибочная строка в режиме по умолчанию; также код неверных аргументов командной строки (argparse) |

### Исключения

Все ошибки пакета наследуются от `StreamStatsError` (кроме `ErrorOrWarningLevelError`):

- `UnsupportedFormatError` — неподдерживаемый формат.
- `IncorrectDateError` — неверная временная метка.
- `DifferentTypesError` — разные форматы входных файлов.

и т.д.

## Логирование

Записывается только предупреждение `WARNING` для каждой пропущенной строки в режиме `--skip-invalid`, с указанием файла и номера строки.
